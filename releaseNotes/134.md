## 1.3.4

### Fixes

- **Windows: the opencode CLI is executed as a real executable again.** `where opencode` was only
  used to check that the command exists, and the plugin then ran the bare name `opencode`. Java
  starts a process through `CreateProcess`, which only appends `.exe` to a bare name and ignores
  `PATHEXT`, so an install from Scoop or npm — where `PATH` leads with the extensionless POSIX
  launcher and the Windows entry point is `opencode.cmd` — was *detected* but never ran:
  `CreateProcess error=2, The system cannot find the file specified`, followed by
  "OpenCode service unavailable". The CLI lookup now parses the `where opencode` output and keeps
  the first `.exe`/`.com`/`.cmd`/`.bat` entry, so service discovery and the terminal both start the
  Windows entry point (issue #2).
