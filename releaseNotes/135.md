## 1.3.5

### Fixes

- **Closing one IDE window no longer kills another window's terminal.** The terminal widgets live
  in a registry that is shared by every project in the IDE process, but project disposal called
  `clearAll()` and disposed *every* widget. With two project windows open, closing one of them
  destroyed the other window's terminal shell — the other window's plugin printed
  `zsh: warning: 1 jobs SIGHUPed` and its connection state was left pointing at a dead widget.
  The registry is now scoped by the owning project, and `dispose()` only tears down its own
  widgets. The terminal is no longer notified during teardown, so project disposal cannot
  re-enter the connection reset.
- **Reconnecting actually rediscovers the local service.** After the background service restarted
  (it usually comes back on a different port) the connection manager kept retrying the stale
  endpoint forever. The plugin now asks `opencode service status` — starting the service when it
  is gone — and, when the endpoint changed, rebuilds the API client, the SSE stream and the
  terminal against the new endpoint by itself. Rediscovery is throttled, so a transient network
  blip never restarts a working terminal.
- **The "Connection lost" dialog can now reconnect.** Its `Reconnect` button was a no-op: only the
  `New` branch had code. `Reconnect` now restarts the current mode, `New` still opens the connect
  dialog, and the dialog rearms after a successful reconnect instead of appearing at most once per
  IDE session.
- **The working directory survives a reconnect.** The `Working directory` chosen in the connect
  dialog was dropped when the terminal was restarted; it is now kept and reused.
