## 1.2.0

### New Features

- **opencode v2 support**: The plugin now targets opencode **v2** instead of v1.
  - **Local sessions** attach to the opencode v2 **background service**. The plugin starts it when
    needed (`opencode service start`), reads its URL from `opencode service status`, and reads the
    Basic auth password from `service.json` in the opencode config directory
    (`~/.config/opencode`, or `%APPDATA%\opencode` on Windows).
  - The OpenCode terminal tab launches the v2 TUI (`opencode [--continue]`); the TUI auto-connects to
    the same background service the plugin talks to.
  - **Remote / existing server** connections still work: enter `host:port` and the password printed
    by `opencode serve` on the remote machine.
  - Web mode now points at the v2 `/doc` route.

### Changes

- The connect dialog **password is now required**: opencode v2 requires HTTP Basic auth
  (`opencode:<password>`) on every `/api` request.
- The dialog **port field is ignored for local sessions** — the background service owns its port.
  The terminal tab title shows the discovered port, e.g. `OpenCode(49374)`.

### Fixes

- Diff review, session status/discovery, completion notifications and `@`-reference injection were
  ported to the v2 `/api` HTTP + SSE surface (new `session.execution.*` and `session.step.ended`
  events, the `{data: ...}` response envelope, and the `session.step.ended` `patch`-based diff).
- `@`-references are now typed into the TUI terminal instead of the removed `/tui/append-prompt`
  route.
